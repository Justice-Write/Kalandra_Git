# Kalandra — Sandboxed Writes (the `data_engine/` boundary)

*Describes what the code does today (2026-10-04). Companion to
`docs/PRIVACY.md` and `docs/SECURITY_AND_PRIVACY.md` §5 item 7.*

## The rule

Everything Kalandra creates on its own initiative is written under **one
folder: `data_engine/`** inside the project root (the folder `main.py` lives
in). Secrets are the one thing that never touches disk at all — they go to
the OS keychain via `keyring` (`core_engine/account_manager.py`).

The boundary is a **convention enforced by construction**, not by a central
path-validation function: every module that writes declares its target as a
fixed path under `data_engine/`, and no write path is built from user or
network input without that prefix. There is no `safe_path()`-style guard in
the code today — see "Escape attempts" below.

## Writes that are *outside* `data_engine/` on purpose

These are the only places the app writes elsewhere, and each one is a file
the **user explicitly pointed at**:

- **Filter Editor** — rewrites the `.filter` file you opened, after saving a
  `.bak` next to it (`core_engine/filter_editor.py:245-248`,
  `gui_overlay/dashboard.py:1254`).
- **Obsidian export** — writes into the vault folder you configured
  (`core_engine/obsidian_export.py`, path from `data_engine/config.json`).
- **Path of Building** — Kalandra *reads* PoB's `Builds` folders
  (`pob_bridge.py:39-53,154-155`); it does not write there. [OWNER CONFIRM]
- **OS keychain** — secrets only (`account_manager.py`).
- **Uninstaller** — may copy the DB to `Documents\Kalandra-Data` if you say
  yes (see `docs/PRIVACY.md`).

## Escape attempts (`..`, absolute paths, symlinks)

Today there is **no runtime check** that rejects a path escaping
`data_engine/`. The protection is that no write path in the engine is
composed from untrusted input: file names under `characters/`, `deaths/`
and `item_art/` are slugs/timestamps generated by the code, not raw user
strings. The one user-controlled directory setting, `dir_database`, is
trusted as-is (it is your own config file).

If you want a hard guard, `tests/sandbox_write_checks.py::under_data_engine`
is the reference check (realpath + prefix compare); promoting it into
`core_engine` as a shared helper is the obvious next step. [OWNER CONFIRM]
whether to add that helper before release.

## How to verify

```
python tests/sandbox_write_checks.py   # declared write roots resolve under data_engine/
python tests/stress_test.py            # full adversarial suite
```

`sandbox_write_checks.py` imports the modules above, asserts every declared
root resolves inside `<project>/data_engine/`, and includes negative controls
(`..`, sibling-dir, absolute foreign path) so the check itself cannot
silently pass. Add a line to its `ROOTS` dict whenever a new module gains a
write target.
